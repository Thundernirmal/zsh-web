# Zsh documentation website: architecture and UX audit

**Completed:** 5 September 2026. Live observations began 4 September.

**Website:** https://zsh.nirmalkatariya.com/

**Source reviewed:** `Thundernirmal/zsh-web` at `803a8df179a9870cdf9ac91f3cd5f8ea954d6d49`.

**Shell source used for comparison:** `Thundernirmal/zsh` at `8233c85ad52bd1e17d82cb1e7e05f944a227f00d`.

## Verdict

Keep Astro, the React search islands, and the Catppuccin visual language. The site is cohesive and the core interactions tested work. Its biggest weaknesses are documentation accuracy, access to the actual reference content, and the journey from finding a command to using it correctly.

The highest-priority confirmed issue is contradictory fzf requirements generated by the extractor. A second architectural priority is providing static access to command details: currently the essential reference content is only mounted after a JavaScript-driven expansion.

No critical security vulnerability was confirmed. This review does not certify security, accessibility conformance, mobile behavior, or performance scores.

## Scope and evidence

### Completed

- Retrieved 68 text files from the pinned website commit and verified their exact Git blob hashes.
- Reviewed the extraction pipeline, generated datasets, Astro routes/layout, search/tips islands, UI primitives relevant to findings, styles, clipboard handling, keyboard hook, CI, budget script and browser tests.
- Inspected the live homepage, command library and tips page in desktop Chrome, including screenshots and rendered DOM.
- Tested command search, expansion, category selection with keyboard, actual clipboard contents, URL updates, tips search, empty-state recovery, additional-tip loading and homepage roulette.
- Tested direct arrival at the ztheme command URL and measured the expanded command's position.
- Ran extractor verification against the shell snapshot: **47 commands and 60 tips verified successfully**.
- Ran Node syntax checks on `scripts/extract.mjs` and `scripts/check-budget.mjs`: passed.

### Limits

- No production build, full `npm run verify`, repository Playwright matrix, automated axe run, Lighthouse run, or dependency vulnerability scan was executed here. Astro and project test dependencies were unavailable locally.
- Mobile behavior was reviewed through responsive source and existing tests, not independently exercised on a mobile viewport/device. Do not read this report as a mobile QA pass.
- Deployed HTTP security headers and HTTP status codes were not independently verified. Header findings refer to `public/_headers`.
- The deployed commit identifier is not exposed in the UI; live findings are attributed to the observed site, while code findings are pinned to the source commit above.
- Console errors retrieved during the tested flows originated from a `chrome-extension://` content script. They were excluded from site defects. No site-origin error appeared in that retrieved sample.

## Architecture assessment

| Layer | Current design | Assessment |
|---|---|---|
| Shell documentation source | Local shell implementation, GUIDE and help/tips catalogues | Good foundation for source-backed documentation |
| Extraction | 1,012-line Node script parses implementations, registries and documentation | Central point of semantic fragility; string matching is doing too much inference |
| Data | Committed commands/tips JSON | Deterministic site builds; explicit updates are required |
| Validation | Zod-backed Astro Content Collections | Good shape validation; does not catch contradictory meaning |
| Rendering | Static Astro routes for home, commands, tips and 404 | Correct framework choice for a small documentation site |
| Interactivity | React SearchCommands/TipsExplorer using `client:visible`; Astro-native tip roulette | Sensible split; no reason to hydrate the homepage with React |
| UI system | Base UI/shadcn primitives, Tailwind v4, semantic Catppuccin tokens, shared category registry | Consistent and reusable; a few caller-level accessibility mistakes remain |
| State | Local React state mirrored into query parameters | Shareable state works; deep-link landing and navigation semantics need improvement |
| Hosting | Static Cloudflare Pages output, cache/security header configuration | Low operational complexity; production verification should be explicit |
| CI | Sync validation, lint, dead-code checks, build, HTML budgets and Chromium desktop/mobile tests | Strong intent; meaningful gaps in semantic, failure-state and payload coverage |

The intended data flow is shell sources → extractor → committed JSON → validated Astro collections → static pages and serialized island data → hydrated search/details. Cloudflare builds consume committed data, not the shell repository directly.

The architecture should stay static. The recommended changes are small structural improvements rather than a framework migration:

1. Export structured command metadata from the shell project: dependency versions, available modes, syntax, runnable examples, mutation status and notes. Avoid inferring public capabilities from private helper names.
2. Split extraction into parsing, normalization, semantic validation and deterministic serialization. Give each stage fixtures.
3. Add a source manifest with shell commit, extractor schema version and generation time; display the source commit and a human-readable sync date.
4. Give commands static detail pages or an accessible static fallback. Keep search as an enhancement.
5. Split the 723-line SearchCommands component into URL-state logic, filtering, result rows and detail rendering. Preserve the existing hydration policy unless measured evidence justifies changing it.

## Findings

### H1 — Generated dependency guidance contradicts itself

**Priority:** high for documentation correctness. **Evidence:** live UI, committed data and extractor.

**Status: fixed** — `scripts/extract.mjs` now reads `_FZF_MIN_VERSION` from `40-fzf.zsh` (the shell's single authoritative floor) and generates availability text from it. A `validateCommandSemantics` gate rejects any availability/dependency string quoting a different fzf version, so sync fails loudly on future drift. Regenerated `fbr`, `fkill`, and `zi` show fzf 0.68.0+ everywhere.

The live `fbr` details show both:

- Availability: fzf **0.52.0+** is ready.
- Dependencies: git and fzf **0.68.0+**.

The same contradiction exists in `fkill` and `zi`. The shell config requires 0.68.0+. The older version is hard-coded in `HELP_CHECK_AVAILABILITY`, while the dependency string comes from the shell catalogue.

Crucially, **sync verification passes with this contradiction**. Regenerating JSON alone will reproduce the bug; this is not simply an out-of-date deployment.

**Fix:** derive the minimum fzf version from one authoritative field. Add semantic assertions that availability and dependencies agree for every entry. Rebuild both datasets after fixing the extractor.

[Extractor lines 47–60](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/scripts/extract.mjs#L47-L60), [generated data](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/src/data/commands.json#L204-L215).

### M1 — “Copy Command” copies syntax placeholders

**Priority:** medium. **Evidence:** live clipboard verification and source.

**Status: fixed** — the function syntax block is now labeled "Syntax" and its copy action hands over the command's first concrete example (annotation stripped), with an explicit "Copy example: …" name; commands without examples would fall back to an explicit "Copy syntax template". Alias blocks keep "Expands To" with a "Copy expansion" action. Per-example copy buttons are preserved, and a clipboard e2e test asserts `upkg` copies the runnable `upkg`, not the template.

Clicking Copy Command for `upkg` copied exactly `upkg [command] [args] [flags]`. This is a syntax template, not a runnable invocation. Sixteen function records contain angle- or square-bracket placeholders in their command field. In Zsh, these characters may trigger globbing or redirection rather than acting as harmless documentation notation.

**Fix:** label this block “Syntax.” Either remove its copy action or explicitly label it “Copy syntax template.” Make the prominent action copy a concrete example. Preserve the existing example-specific copy buttons; they already strip annotations.

[Extractor assignment](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/scripts/extract.mjs#L830-L858), [detail rendering](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/src/components/SearchCommands.tsx#L588-L650).

### M2 — Filter-removal chips cannot be focused by keyboard

**Priority:** medium accessibility defect. **Evidence:** live DOM and source.

**Status: fixed** — the three removal chips are now real `button` elements (Base UI `render`), each with an explicit name ("Remove query/type/category filter: …"), visible focus styles from the badge focus ring, and a 44px touch target on mobile. A keyboard e2e test applies query + type + category filters and removes all three chips with Enter; two pre-existing tests that matched chips only by a loose `/upkg/i` button regex were tightened to the accordion trigger.

The active query chip is a `SPAN`, with no role and `tabIndex=-1`, despite an `onClick` that clears the query. Type and category chips use the same pattern. Keyboard users can use Reset all, but cannot activate the individual removal controls as mouse users can.

**Fix:** render native buttons with names such as “Remove category filter: Git,” visible focus styles and practical touch targets. Test all three chips after applying filters; the existing axe checks inspect default route states and cannot establish that this state is accessible.

[Filter chips](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/src/components/SearchCommands.tsx#L503-L535), [Badge defaults to span](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/src/components/ui/badge.tsx).

### M3 — Direct command links open the item offscreen

**Priority:** medium. **Evidence:** live reproduction.

Opening the ztheme link expanded the correct command but left the page at `scrollY=0`. The trigger was at approximately **4,178px from the viewport top**, while the viewport height was **936px**. The recipient sees the top of the full list, not the command they were sent.

**Fix:** after initial URL restoration and rendering, scroll the selected command into view with header offset. Avoid moving focus on every search keystroke; deliberate direct-link navigation can focus a suitable heading. Test near-top and near-bottom commands.

[Verified direct link](https://zsh.nirmalkatariya.com/commands/?command=function%3Aztheme), [URL restoration](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/src/components/SearchCommands.tsx#L283-L320).

### M4 — Essential reference content requires JavaScript

**Priority:** medium resilience/accessibility issue; high architectural value to fix. **Evidence:** source.

Initial expanded state is empty, and detail bodies are only mounted when that state includes the command ID. Static HTML therefore contains summaries but not the reference bodies. If JavaScript fails or is disabled, users cannot open the actual command documentation. Browser Find cannot reveal content that has never been mounted; `hiddenUntilFound` does not solve that absence.

**Fix:** generate static per-command pages with usage, requirements, examples and caveats. Alternatively, provide a full static reference with native disclosures. Keep the fast list/search UI and modest initial DOM budget. Do not fix this by blindly mounting every duplicated desktop/mobile table into the list.

[Conditional detail mounting](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/src/components/SearchCommands.tsx#L621-L627), [route](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/src/pages/commands.astro).

### M5 — Capability badges infer semantics from implementation details

**Priority:** medium content-model defect. **Evidence:** source and live fbr details.

**Status: fixed** — the extractor no longer publishes `plainMode`/`richOutput` as command capabilities; `_ui_plain_mode`/`_ui_title_line` references now produce a single `terminalAdaptive` fact, rendered as "Adapts to terminal" (styled in rich terminals, plain otherwise). "Interactive" is labeled "Interactive terminal". Tips in the unconditional pool now quote the referenced command's own availability (croot no longer claims "Always available" while needing git); conditional-pool tips keep their genuine runtime conditions.

The extractor sets `plainMode` when it finds `_ui_plain_mode` anywhere in the inspected body. On `fbr`, that helper controls decoration; the function still requires an interactive terminal and fzf. The live page displays “Interactive” and “Plain Mode” together without explaining the distinction.

Similarly, tip availability is derived from the conditions that include a tip, which are not always the prerequisites for executing the action. For example, the live croot tip says “Always available,” although using it requires Git and a repository context.

**Fix:** explicitly distinguish plain styling, noninteractive support, installation prerequisites and runtime context. Use “Always shown by tips” only if that is the intended meaning; use actual requirements for a public command guide.

[Capability inference](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/scripts/extract.mjs#L640-L670), [tip extraction](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/scripts/extract.mjs#L863-L888).

### M6 — Copy failure is silent

**Priority:** medium usability issue. **Evidence:** source; failure was not injected live.

When the Clipboard API rejects, the catch handler simply clears the success state. There is no error, retry guidance or manual-copy fallback, so the button appears to do nothing.

**Fix:** announce “Could not copy; select the text manually,” preserve selectable text and optionally provide a retry. Test success and rejection. Clear pending feedback timers when unmounting or starting a new copy.

[CopyButton](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/src/components/CopyButton.tsx).

### M7 — The performance gate omits JavaScript and fonts

**Priority:** medium verification gap. **Evidence:** budget script.

The budget measures raw/gzipped HTML and opening tags for three routes. It does not count external JavaScript, CSS, fonts, hydrated DOM growth or interaction cost. The site can therefore pass while shipping a larger React/UI bundle. Three font families are imported, with two globally preloaded and the mono font additionally preloaded on home.

**Fix:** budget route-level compressed JS/CSS/font transfers and expanded-state DOM separately. Measure search responsiveness and initial useful content under mobile CPU/network constraints. Keep fonts if measurements justify them; this audit did not establish that the site is slow.

[Budget script](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/scripts/check-budget.mjs), [font preloads](https://github.com/Thundernirmal/zsh-web/blob/803a8df179a9870cdf9ac91f3cd5f8ea954d6d49/src/layouts/Layout.astro).

## Product and visual UX recommendations

### Homepage and onboarding

The typography, restrained purple accents, terminal illustration and consistent content width work well. The terminal illustration dominates the initial desktop view, while the prominent Browse Commands CTA sits much lower. The header link remains available, so this is hierarchy friction rather than blocked navigation.

Move two clear actions directly below the introduction: **Browse Commands** and **Get Started**. The latter should explain GNU/Linux scope, installation location, dependencies, loading after OMZ/compinit, and the first useful command. A brief troubleshooting page should cover missing commands, unsupported fzf, unavailable Secret Service and font issues.

The current primary navigation only offers Commands and Tips. A first-time visitor can discover commands without learning how to obtain the configuration. Link directly to the shell GUIDE as an immediate improvement, then add task-oriented setup material.

### Command rows and details

- Keep command name and plain-language summary prominent. Move source filenames into expanded details and make them exact, commit-pinned links. `Lib/functions Catalogue.zsh` is neither a friendly label nor an accurate file path.
- Replace redundant statistics such as “47 total commands” and “47 entries with extracted details” with useful navigation or compact summary text.
- Order details as purpose → runnable example → syntax → requirements → options → caveats/source.
- Collapse alias-only subcommand rows into concise “Also known as” text where appropriate. Large tables currently repeat many synonyms without adding much guidance.
- Put mutation warnings beside the relevant copyable example, not solely in a long Notes block.
- Add an explicit Copy link action. The CopyButton supports a link icon but command rows do not expose a share action.
- Improve search with token matching and exact-name ranking. Current search is contiguous substring matching across the whole record; this is functional, but task queries and typos are less forgiving.

### Tips

Search, empty recovery, “Show More” and roulette worked in the tested live flows. Make command names within tips link to their documentation, and offer copying only for identified runnable examples. The current tips are largely an informational dead end. A selected tip should help the visitor do something next.

### Mobile and accessibility

The responsive source is thoughtful: 44px mobile navigation/filter targets, 16px search input text, stacked definition-list details below the desktop breakpoint, safe-area padding, and a header that reappears on focus. The mobile tests explicitly cover several narrow widths and landscape. These are strengths, but the tests were reviewed rather than rerun.

Improve the remaining small copy buttons from 28px to approximately 44px on touch layouts. This is an ergonomic recommendation, not a blanket claim of WCAG failure. Test expanded long package examples, 200% text sizing, 400% reflow, keyboard navigation with the header hidden, and real mobile Safari as well as Chromium.

Keep the dark theme; an optional light theme would help daylight reading but is lower priority than the confirmed defects. Preserve reduced-motion support and visible focus styles.

## SEO, security and delivery

**SEO:** route titles, descriptions, canonicals, social metadata, robots and sitemap support exist. Static command detail pages would provide stronger indexable content and command-specific share previews. Query-only command views currently share the route's generic metadata. No claim is made about actual search-engine indexing.

**Security:** the repository config includes CSP, frame restrictions, nosniff, referrer and permissions policies. `script-src 'unsafe-inline'` weakens CSP's protection against injected inline scripts; consider build-generated hashes for known inline blocks if feasible. This is defense in depth, not evidence of an exploit. Do not relax CSP or other policies to suppress browser-extension errors. Keep source-controlled command text rendered as text rather than evaluating it.

**Sync/delivery:** the site labels entries “live,” but data is a committed snapshot. The observed JSON does match the audited shell snapshot; there is no evidence that all content is currently stale. However, website CI is triggered by website changes and checks out the shell's unpinned default branch. Shell-only changes do not automatically refresh this repository, while rerunning old website commits can compare against newer shell behavior.

Pin the intended shell commit in a manifest and create a deliberate update mechanism that refreshes it and opens a reviewable data update. Display “Generated from shell commit …” instead of implying a live connection. Keep deployment deterministic.

## Verification improvements and delivery order

1. **Fix content semantics:** remove hard-coded fzf versions; explicitly model capabilities; add cross-field consistency tests. Acceptance: fbr, fkill and zi show one correct requirement everywhere, and sync checks reject contradictions.
2. **Fix direct interactions:** accessible chip buttons, syntax/example distinction, deep-link scrolling, copy-failure feedback. Acceptance: keyboard-only use can remove individual filters; copied examples are runnable; a direct ztheme link lands on ztheme.
3. **Make documentation independently readable:** static command pages and a visible setup guide. Acceptance: a no-JavaScript visitor can read complete usage and caveats.
4. **Improve hierarchy and connections:** prominent homepage actions, simpler result metadata, clickable tip-to-command references and explicit sharing.
5. **Strengthen assurance:** budget JS/fonts, test expanded/filter/error states, and add Safari/Firefox plus real mobile checks. The existing accessibility test only fails critical/serious axe results on initial routes; expand state coverage and assess moderate findings deliberately.

Preserve the existing static framework, deterministic builds, semantic theme tokens, accessible primitive choices, reduced-motion handling and lazy homepage tips. The project needs more reliable documentation semantics and smoother task completion, not a new stack.

## Remediation after the shell architecture rewrite

The original observations above remain historical evidence. The earlier H1, M1,
M2 and M5 fixes are retained and revalidated against the rewritten shell.

### Ordered implementation stages

1. **Source contract and reproducible sync.** Adapt registry parsing, domain implementation discovery, action records and GUIDE coverage together; regenerate data and pin CI to the source manifest. This must precede UI work because command counts, kinds and source paths changed.
2. **Reference access and navigation (M3/M4).** Build static command pages, source links and sharing destinations together, then finish deep-link landing and search. This avoids building a second temporary link scheme.
3. **Task completion (M6 and UX recommendations).** Finish clipboard feedback/touch targets, setup and troubleshooting, homepage actions and tip-to-reference connections using the stage 2 destinations.
4. **Assurance (M7).** Measure and gate the finished routes and expanded states; extend accessibility/browser coverage. Record external/manual checks separately from automated evidence.

### Stage 1 — source contract

- Registry records now come from `lib/command-registry.zsh`; public function documentation comes from the actual domain files, while help/tips retain their lazy catalogues.
- Added the shell's action kind and Secret Service health requirement. GUIDE validation checks runnable action syntax rather than synthetic palette IDs.
- Autoload parsing now recognizes declarations instead of matching quoted diagnostic prose.
- Generated snapshot: 53 commands and 70 tips from shell commit `a7950424c421258bebe5ef1d4decfc443778e11c`.
- `src/data/source.json` records the clean source commit, deterministic source date and schema version. CI checks out that revision; README documents deliberate updates.
- Validation: `npm run verify` passed; all 34 desktop/mobile Playwright tests passed. Added action rendering coverage, corrected the two-result upkg expectation, wrapped type controls at narrow landscape widths, and made the URL test poll keyboard hydration before filling.

### Stage 2 — readable reference and navigation

- M3: restored query links scroll once to the expanded command with header clearance and focus its trigger. Conflicting filters are cleared only when they would hide the direct target; normal search does not move focus or scroll.
- M4: all 53 commands now have static detail routes, command-specific metadata and ordinary links in the search list. JavaScript-disabled readers receive the full example, syntax, requirements, options and notes.
- Extracted `CommandDetails` from the search island so static pages and expanded results share one presentation. Existing search/tips `client:visible` policies are preserved.
- Detail pages lead with a concrete example. Source filenames now appear in details as exact commit-pinned links; Copy link uses the static destination. Removed redundant command statistic cards and displayed source revision/date in the footer.
- Search matches all query tokens and ranks an exact command name first.
- Validation: `npm run verify` passed; all 44 desktop/mobile Playwright tests passed, including no-JavaScript reading, near-top/bottom direct links, token search and copied permanent URLs. Command index HTML decreased from 319,406 to 290,224 bytes without raising budgets.
